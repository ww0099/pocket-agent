## 1. 新增保障

### 1.1 `--check` 临时目录告警

`agent.cmd --check` 现在输出：

```text
TEMP：E:\agent\data\tmp
TMP：E:\agent\data\tmp
```

如果 TEMP/TMP 位于 C 盘，会额外输出：

```text
⚠ 临时目录位于 C 盘；请通过 agent.cmd 启动，启动器会重定向到 U 盘 data\tmp
```

已用两种方式验证：正常启动（E 盘）无告警；手动把 TEMP 设为 `C:\Windows\Temp` 后告警出现。

### 1.2 C 盘写入审计

新增 `scripts/audit-c-writes.mjs`（不需要管理员权限）：

- 监视 `C:\Users\<user>\AppData\Local\Temp` 与 C 盘 npm 缓存；
- 通过 `agent.cmd` 执行一次真实工具任务（Write → Read → 回复）；
- 若观察到 C 盘写入事件则失败。

本次结果：

```text
exit: 0
stdout: "C_AUDIT_OK"
c_events: 0
C_AUDIT_OK（未观察到 C 盘 Temp/npm 缓存写入）
```

> 说明：当前会话不是管理员，未加载 Process Monitor 驱动；完整的内核级审计建议在干净虚拟机中以管理员运行 Procmon，并把日志保存到 D/E 盘。

## 5. 升级脚本

新增：

- `E:\agent\upgrade.ps1`
- `E:\agent\upgrade.cmd`

用法：

```powershell
E:\agent\upgrade.cmd -Source D:\新版本目录
```

行为：

1. 校验源目录存在 `app\dist\cli.js`；
2. 备份当前 `app / runtime / tools` 到 `backup\<时间戳>`；
3. 只替换 `app / runtime / tools`（以及 `docs`、`VERSION.json`）；
4. **不触碰** `config / data / memory / skills / agents / commands`；
5. 运行 `agent.cmd --check` 验证。

已在临时目标目录实测：新 app/runtime 生效、config/data 保留、docs 更新、backup 生成、检查 exit 0。

## 7. TUI 实测反馈修复（2026-10-22 晚）

用户首次 TUI 实测发现并已修复：

| 反馈 | 原因 | 修复 |
|---|---|---|
| `/cost` 显示“未配置价格” | 未填写单价，token 统计本身正常 | 文案改为“仅统计 token”；在 `config\providers.json` 的 `pricing` 标出填写位置。工具不猜服务商价格 |
| `/model deepseek-flash` 状态栏未切换 | Enter 依赖 `ink-text-input` 的 onSubmit，快速输入时可能拿到旧值 | Enter 改由 App 统一处理；自动化测试验证状态栏变为 `deepseek/deepseek-flash` |
| 按 `d` 后 denied.txt 仍被创建、permissions.json 未生成 | 单字母审批键可能被中文输入法吞掉，或审批框尚未出现时按键无效 | 审批改为 **↑/↓ 选择 + Enter 确认** 菜单（输入法无关），保留 a/Shift+A/d 快捷键 |
| 审批决策无法事后核对 | 会话只记录工具结果 | 每次权限决策写入 JSONL：`{"type":"permission","tool","behavior","reason"}` |
| TodoWrite 触发写审批 | 只改内存却被标记为非只读 | 改为不触发权限审批 |

自动化测试增至 **29 个文件 / 138 个测试**，覆盖：
- `/model` 后状态栏更新；
- `d` 拒绝、`a` 允许、↑/↓+Enter 始终允许；
- 始终允许后 `.agent\permissions.json` 生成；
- 权限决策审计记录。

### 7.1 第二次 TUI 实测：审批竞态修复

第二次复测中 `denied2.txt` 仍被创建。会话审计显示两次 Write 都记录为：

```json
{"type":"permission","tool":"Write","behavior":"allow","reason":"用户已授权"}
```

且 `.agent\permissions.json` 未生成，说明两次都落在“允许本次”（index 0）。

根因：用户快速按 `↓↓` 后立刻 Enter，React 状态尚未刷新，Enter 读到旧的 `approvalIndex=0`。

修复：

1. 用 `useRef` 同步保存审批选择，Enter 直接读 ref，不再依赖 React 渲染时序；
2. **必须先显式选择**，未选择时 Enter 不生效（防止输入法提交用的 Enter 误授权）；
3. 新增数字选择：`1` 允许本次、`2` 本项目始终允许、`3` 拒绝，再按 Enter；
4. 保留 `↑/↓`、`Tab` 与 `a / Shift+A / d`；
5. 自动化测试覆盖“快速 ↓↓+Enter”和“未选择时 Enter 不授权”。

当前审批交互以数字选择最稳，尤其适合中文输入法环境。
