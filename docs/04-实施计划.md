# 04 · 实施计划

> 版本：0.1（2026-10-22）  
> 交付目标：`E:\agent` 上的可运行便携 Agent  
> 开发方式：分阶段、每阶段有明确验收门；前一阶段不达标不进入下一阶段

---

## 0. 工作区约定

| 用途 | 位置 | 说明 |
|---|---|---|
| 交付目录（最终产物） | `E:\agent` | 用户插入 U 盘即可使用；本目录同时存放项目文档 |
| 开发工作区（源码） | `D:\Myproject(AI)\pocket-agent` | `node_modules`、构建缓存放 D 盘，避免 U 盘小文件性能问题 |
| 构建装配 | `D:\...\pocket-agent\scripts\assemble.ps1` | 构建完成后增量复制到 `E:\agent`（不覆盖用户数据目录） |
| 备份 | `E:\agent\backup\<版本>` | 升级前备份 `app/tools/runtime` |

> 文档以 `E:\agent\docs` 为准；仓库 `docs/` 在每次装配时同步，便于版本管理。

## 2. M1 · 骨架与模型接入

### 目标

跑通"最小可用 Agent"：命令行启动 → 加载配置 → 调用模型 → 流式输出 → 无工具（或仅 Read）也能对话。

### 任务

1. **项目初始化**
   - `package.json`（ESM、scripts）、`tsconfig.json`、`biome.json`、`.gitignore`
   - 目录骨架（见架构文档第 5 节）
2. **根路径与配置**
   - `resolveAgentRoot()`、`paths.ts`（所有路径集中定义）
   - JSONC 加载 + zod 校验 + 友好错误
   - Provider 配置结构与默认模板
3. **密钥管理**
   - 环境变量 / `secrets.json` 读取
   - 日志脱敏中间件
4. **Provider 适配器**
   - `Provider` 接口、统一消息模型、事件类型
   - Anthropic 适配器（stream + tool_use + usage）
   - OpenAI 兼容适配器（stream + tool_calls + usage）
   - 重试与超时（429/5xx 指数退避，可取消）
5. **最小内核**
   - `agentLoop()`：无工具版本，先打通流式与用量
   - headless 输出（plain）
6. **测试**
   - SSE fixture 回放：两家各 3 个用例（纯文本、工具调用、错误）
   - 配置校验单元测试

### 验收门（全部满足才进 M2）

- [ ] `node dist/cli.js -p "你好"` 在 Anthropic 与至少一家 OpenAI 兼容服务上返回流式文本
- [ ] 流式输出可被 Ctrl+C 中止，进程正常退出
- [ ] 429 场景触发重试，最终成功或给出可行动错误
- [ ] 日志中不出现 API Key 原文
- [ ] 单元测试通过，构建产物可独立运行

## 3. M2 · 核心工具、权限与会话

### 目标

从"能聊天"变成"能干活"：读写文件、搜索、执行命令，并且有安全边界和会话记录。

### 任务

1. **工具基础设施**
   - `Tool` 接口、`buildTool()` 默认值、ToolContext
   - 工具注册表、schema 校验、错误封装
2. **核心工具**
   - `Read`（offset/limit、行号、二进制检测）
   - `Write`（先 Read 校验、原子写）
   - `Edit`（精确替换、replace_all、失败时给出最接近片段）
   - `Glob`（tinyglobby，忽略规则）
   - `Grep`（ripgrep 子进程 + JSON 解析 + 降级）
   - `Bash`（PowerShell/cmd、超时、后台、输出截断）
   - `TodoWrite`
3. **权限系统**
   - 规则解析与匹配（allow/deny/ask）
   - 四种模式（default/acceptEdits/plan/bypass）
   - 非交互模式的默认策略（headless 下 ask → deny）
   - 路径守卫（工作区边界、敏感路径黑名单）
   - 危险命令识别
4. **工具调度**
   - 并发/串行分批
   - 结果截断与全文落盘
5. **会话**
   - JSONL 写入、索引、尾行修复
   - `--continue` / `--resume`
6. **测试**
   - 每个工具的单元测试（临时目录）
   - 权限矩阵测试（规则 × 模式 × 工具）
   - 崩溃模拟：写入中断后文件仍可读

### 验收门

- [ ] 在示例仓库中完成："找出 bug → 修改 → 运行测试 → 确认通过"
- [ ] 越界路径（工作目录外）默认被拒绝，授权后可访问
- [ ] `rm -rf`、`format` 等命令被拦截并要求确认
- [ ] 强杀进程后 `--continue` 能恢复，消息完整
- [ ] 只读工具并发执行，写操作严格串行

## 4. M3 · 交互式 TUI

### 目标

达到"愿意每天用"的交互体验，而不只是能跑。

### 任务

1. **Ink 应用骨架**
   - App 状态（消息、流式文本、工具状态、审批队列、任务清单）
   - 输入框（多行、历史、粘贴、`@文件` 补全）
   - 消息列表（Markdown 渲染、代码高亮、折叠长输出）
2. **流式渲染**
   - 增量文本、工具调用卡片（运行中/成功/失败/耗时）
   - Ctrl+C 取消当前请求（不退出程序）
3. **审批交互**
   - 允许本次 / 本项目始终允许 / 拒绝 / 编辑命令
   - 选择持久化到项目 `.agent\permissions.json`
4. **斜杠命令**
   - `/help` `/clear` `/compact` `/model` `/provider` `/cost` `/permissions` `/doctor` `/resume` `/version`
5. **状态栏**
   - 当前模型、Provider、token 用量、权限模式、Git 分支
6. **降级**
   - `--plain` 纯文本模式；不支持的终端自动降级
7. **测试**
   - 渲染快照测试（Ink testing library）
   - 审批流程状态机测试

### 验收门

- [ ] 连续对话 30 轮，界面无错位、无闪烁
- [ ] 工具调用状态实时可见，失败有原因
- [ ] 审批弹窗可用键盘完成全部选项
- [ ] Windows Terminal 与 conhost 均可正常使用
- [ ] `--plain` 与 TUI 行为一致（除渲染）

## 5. M4 · 上下文、记忆与长会话

### 目标

让 Agent 在真实长任务中不"失忆"、不撑爆、不崩溃。

### 任务

1. **系统提示组装**
   - 身份、环境、工具准则、权限说明
   - 记忆注入（全局 + 项目，截断保护）
   - `AGENTS.md` / `CLAUDE.md` 向上查找
   - 技能/子 Agent 元数据索引
2. **Token 估算与校准**
   - 混合文本估算 + 用量回填校准
3. **压缩**
   - 自动触发阈值（默认 0.75）
   - 手动 `/compact`
   - 压缩后复灌（cwd、改动文件、Todo、已加载技能、权限模式）
   - 压缩失败降级（硬截断 + 保留关键附件）
4. **记忆**
   - `MEMORY.md` 索引读取与硬截断
   - 记忆写入工具（需说明理由）
   - 手工编辑后生效
5. **成本**
   - 价格表配置、`/cost` 展示（标注估算）
6. **测试**
   - 长会话模拟（100+ 轮 fixture）
   - 压缩前后任务连续性测试

### 验收门

- [ ] 连续 50 轮以上对话不崩，压缩后仍记得任务目标
- [ ] `--resume` 后待办、已改文件、摘要一致
- [ ] 超长工具输出不会撑爆上下文

## 8. M7 · 生态适配（预留，v2）

> 用户要求：未来扩展到 Linux / macOS，并完善生态适应性。以下为**预留设计**，不在 v1 交付范围，但从 M1 起就必须避免写死 Windows。

### 8.1 现在就要做的预留（融入 M1~M6）

| 预留项 | 要求 |
|---|---|
| 平台抽象层 | `PlatformAdapter`：路径分隔符、临时目录、shell、换行、可执行文件后缀、文件大小写语义 |
| 运行时目录 | `runtime\<platform>-<arch>\`，v1 只放 `win-x64`，结构支持未来新增 |
| 启动器 | 除 `agent.cmd` 外预留 `agent.sh` / `agent.command` 的位置（v1 可只放占位说明） |
| Shell 工具 | 不写死 PowerShell；按平台选择 `pwsh/powershell`、`bash/zsh`、`cmd` |
| 路径处理 | 统一用 `path` 模块；禁止字符串拼接 `\`；禁止硬编码盘符 |
| 大小写 | 文件比较遵循平台语义（Windows 不敏感、Linux 敏感），不假设其一 |
| 换行 | 读写文本保留原始换行（`\r\n` vs `\n`），不无条件转换 |
| 终端能力 | raw mode、颜色、宽度检测走能力探测而非平台判断 |
| 构建 | 构建脚本接受 `--target win-x64|darwin-arm64|linux-x64` 参数 |
| 测试 | 路径/换行/shell 相关单测参数化，便于未来跨平台跑 |
| 文档 | 所有"仅 Windows"的说明集中标注，避免散落 |

### 8.2 v2 任务（待评估）

1. `runtime` 分平台装配与校验（macOS arm64/x64、Linux x64/arm64）；
2. 启动器 `.sh` / `.command`，处理挂载点变化（`/Volumes/NAME`、`/media/user/NAME`）；
3. 文件系统差异：macOS APFS 大小写不敏感、Linux 权限位、外接盘 noexec 问题；
4. Shell 策略：zsh/bash、交互式命令禁用、信号与进程组处理；
5. 终端兼容：iTerm2 / Terminal.app / GNOME Terminal / Windows Terminal；
6. 跨平台测试矩阵与 CI（GitHub Actions 三平台）；
7. 生态适配：
   - 更多 Provider（Gemini、Azure OpenAI、Bedrock、本地 vLLM）；
   - MCP 生态预设（浏览器、数据库、云服务）；
   - 技能市场/模板（本地目录即可，不依赖云）；
   - 与 VS Code / JetBrains 的轻量集成（可选）。

### 8.3 v2 验收门（预告）

- [ ] 同一 U 盘在 Windows / macOS / Linux 上均可启动（各自运行时）；
- [ ] 会话、记忆、技能跨平台可读，换行与路径不损坏；
- [ ] 三个平台的启动器均正确处理挂载点/盘符变化；
- [ ] CI 在三平台跑通单元与集成测试。

## 10. 风险与应对（实施层）

| 风险 | 触发信号 | 应对 |
|---|---|---|
| Provider 工具调用不兼容 | 模型不调用工具 / 参数解析失败 | 每家做协议回放测试；提供"兼容模式"（串行、简化 schema） |
| Ink 在 conhost 显示异常 | 闪烁、光标错位 | 能力探测 + 自动降级 plain |
| U 盘写入慢导致卡顿 | 会话写入延迟 > 50ms | 批量 flush、日志异步、减少小文件 |
| 杀软拦截 rg.exe | 首次运行失败 | 文档说明；`/doctor` 检测并提示加白 |
| 权限规则过严影响体验 | 频繁弹窗 | 提供项目级允许列表模板；首次运行引导 |
| 范围蔓延 | 不断加功能 | 严格按"不做清单"；新需求进 v1.5/v2 待办 |
| 参考材料合规 | — | 只读分析，不复制源码；提交记录留痕 |
