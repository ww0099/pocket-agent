# 01 · 需求分析

> 版本：0.1（2026-10-22）  
> 状态：已确认方向，待随实施迭代  
> 适用范围：PocketAgent v1（Windows x64）

---

## 1. 一句话定义

PocketAgent 是一个**放在 U 盘里、插上任意 Windows 电脑即可运行**的 AI 编程 Agent：自带运行时与工具链，配置、技能、会话、记忆全部随盘携带，交互与能力对标 Claude Code。

### 1.1 核心价值

| 价值 | 说明 | 可验证信号 |
|---|---|---|
| 即插即用 | 目标机器无需 Node、无需 npm install、无需管理员权限 | 干净 Windows 虚拟机插入 U 盘，双击即可对话 |
| 环境随身 | Provider 配置、权限规则、技能、子 Agent、记忆都随盘 | 换机器后行为一致，无需重新配置 |
| 不污染宿主 | 不写 C 盘、不装服务、不改注册表、不改系统 PATH | Process Monitor 观察无 C 盘持久写入 |
| 可扩展 | MCP / Skills / Subagents / 自定义命令 | 新增一个 MCP server 或技能无需改代码 |
| 可审计 | 会话 JSONL、记忆 Markdown、配置 JSON 明文 | 用户可直接打开查看与删除 |

### 1.2 非目标（v1 明确不做）

- macOS / Linux **v1 不交付**；但必须做平台抽象与预留（见 NFR-13 与《04-实施计划》M7），v2 完成生态适配；
- 图形界面（GUI）；只做终端 TUI 与 headless；
- 浏览器自动化、图像生成、Office 文档处理（放 v1.5+，可通过 MCP 先行接入）；
- 远程控制 / 多机同步 / 云端会话；
- 自动更新（v1 用"覆盖文件 + 版本自检"代替）；
- 与 Claude Code 的配置格式 100% 兼容（只做"可迁移"，不做"完全兼容"）。

## 2. 用户与使用场景

### 2.1 目标用户

- **主用户**：需要在多台电脑间移动工作的开发者（家里 / 公司 / 客户现场 / 临时机器）。
- **次级用户**：受限于公司电脑无法安装软件、但被允许使用便携工具的技术人员。

### 2.2 关键场景

**S1 临时机器救急**
在客户现场的一台陌生 Windows 电脑上，需要快速读懂一个仓库、定位一个 bug、改一行配置。不能安装任何软件，只有 USB 口和网络。

**S2 跨机器连续工作**
上午在公司电脑上与 Agent 讨论到一半，下午回家插上同一 U 盘，执行 `--resume` 继续同一会话，记忆与待办都在。

**S3 受限网络**
目标机器只能访问特定 API 域名（如公司代理白名单）。Agent 必须能配置 base URL / 代理，且除模型调用外全部离线可用（不依赖 npm、不依赖在线更新）。

**S4 团队技能分发**
把团队约定的代码规范、常用命令、审查流程写成 Skills 与自定义命令，放在 U 盘 `skills/`、`commands/` 中，任何人插上即获得同样的工作方式。

**S5 演示与教学**
在一台展示机上安全地运行 Agent：默认只读、危险命令拦截、所有操作可回放（会话 JSONL）。

## 3. 功能需求

优先级：P0 = v1 必须有；P1 = v1 尽量有；P2 = v1.5。

### 3.3 工具能力（v1 工具集）

| 工具 | 语义 | 权限属性 |
|---|---|---|
| `Read` | 读文件，支持 offset/limit；默认上限 2000 行 | 只读 |
| `Write` | 覆盖写文件（要求先 Read） | 写 |
| `Edit` | 精确字符串替换（old_string → new_string），要求先 Read | 写 |
| `Glob` | 按模式查找文件 | 只读 |
| `Grep` | 内容搜索（内置 ripgrep），支持 glob/大小写/输出模式 | 只读 |
| `Bash` | 执行 shell 命令；支持超时、后台运行 | 危险 |
| `TodoWrite` | 维护任务清单 | 无副作用 |
| `Task` | 启动隔离子 Agent，返回结论 | 继承权限 |
| `WebFetch` | 抓取 URL 并转为文本 | 网络 |
| `WebSearch` | 联网搜索（需 Provider 支持或外部搜索 API） | 网络 |
| `Skill` | 按需加载技能正文 | 只读 |

补充要求：

- FR-20：工具输入用 schema 校验，非法输入返回结构化错误而不是崩溃。
- FR-21：工具结果超长时截断（头尾保留），全文写入 `data/tool-outputs/`，并在截断处告知模型全文路径。
- FR-22：只读工具可并发执行；写工具与 Bash 串行执行。
- FR-23：Write / Edit 前必须已读取该文件（防止盲改），文件被外部修改时提示冲突。
- FR-24：Bash 默认使用 PowerShell（`-NoProfile -NonInteractive`），可配置为 Git Bash；禁止交互式命令挂起。

## 5. 验收标准（对标 Claude Code）

从五个维度定义"好用"：

### 5.1 交互体验

- 流式输出平滑，无整段卡顿；Markdown 与代码高亮可读；
- 工具调用有清晰状态（运行中/成功/失败/耗时）；
- 权限询问不打断心流，默认选项安全且合理；
- 支持 Ctrl+C 取消当前生成，支持上下键历史、粘贴多行、`@文件` 补全（P1）。

### 5.2 任务完成度

在以下真实任务上成功率 ≥ 80%：

1. "读懂这个仓库，告诉我入口和主要模块"；
2. "运行测试，定位失败原因并修复"；
3. "新增一个小功能，遵循现有代码风格"；
4. "找出所有硬编码密钥并给出修复方案"（只读模式）；
5. "根据报错日志定位问题"。

### 5.3 上下文治理

- 连续 50 轮以上对话不崩；
- 自动压缩后仍记得任务目标、已改文件、未完成待办；
- 工具输出超长不会撑爆上下文。

### 5.4 扩展性

- 新增一个 MCP Server：只改 `config\mcp.json`；
- 新增一个技能：只加一个 `SKILL.md` 目录；
- 新增一个子 Agent：只加一个 Markdown 文件；
- 新增一个 Provider：改配置即可（无需改代码）。

### 5.5 稳定性

- 连续使用 2 小时无崩溃、无内存持续增长；
- 网络中断、API 429、MCP 超时均能恢复；
- 错误信息可行动（告诉用户下一步怎么做）。

### 5.6 端到端验收脚本（M6）

```text
1. 准备：干净的 Windows 11 虚拟机（无 Node、无 Git、标准用户）
2. 插入 U 盘，双击 agent.cmd
3. 配置一个 Provider 的 API Key
4. 让 Agent 在一个示例仓库中：
   a. 解释项目结构
   b. 修复一个预置的 bug
   c. 运行测试并确认通过
5. 关闭终端，重新打开，--continue 恢复会话
6. 拔盘换到第二台电脑（不同盘符），重复步骤 2、4
7. 检查：C 盘无新增配置文件；会话与记忆完整
```

## 6. 关键假设

| 假设 | 若假设不成立的影响 | 应对 |
|---|---|---|
| 目标机器有 PowerShell 5.1+ | Bash 工具不可用 | 提供 cmd 回退；文档标注最低要求 |
| U 盘为 exFAT 或 NTFS | 大文件/权限/符号链接问题 | 优先 exFAT；NTFS 也可用；不使用符号链接 |
| 目标机器可访问模型 API | 核心功能不可用 | 支持自定义 base URL、代理、本地 Ollama |
| 用户愿意在 U 盘保存 API Key | 每次手动输入 | 提供口令加密 + 环境变量覆盖 |
| 终端支持 ANSI / raw mode | TUI 显示异常 | 提供 `--plain` 纯文本模式 |
| 未来需支持 Linux/macOS | 若现在写死 Windows，重构成本高 | 平台抽象层 + 运行时按平台分目录（v1 即执行） |

## 7. 风险与对策

| 风险 | 等级 | 说明 | 对策 |
|---|---|---|---|
| API Key 随盘丢失 | 高 | U 盘遗失即密钥泄露 | 默认不落盘明文（可选）；支持口令加密；文档强调；`/doctor` 提示风险 |
| exFAT 写入性能与磨损 | 中 | 小文件多导致卡顿、U 盘寿命 | 单文件打包；会话追加写；限制日志滚动 |
| 杀毒软件误报 / SmartScreen | 中 | node.exe 与 rg.exe 首次运行被扫描或拦截 | 使用官方签名二进制；文档说明"更多信息→仍要运行" |
| Windows 终端兼容性 | 中 | conhost 对 raw mode/颜色支持有限 | TUI 降级策略 + `--plain` |
| Provider 工具调用差异 | 高 | 各家的 tool_calls 格式/并行调用/流式行为不同 | 统一适配层 + 每家集成测试 + 失败降级 |
| 上下文窗口差异 | 中 | 便宜模型窗口小，容易撑爆 | 可配置窗口与压缩阈值 |
| 参考资料的合规边界 | 中 | 泄露源码不可复制 | 只做架构分析与独立实现，文档留痕 |
| U 盘热拔导致数据损坏 | 中 | 写入中断 | JSONL 追加 + 原子替换 + 启动时检查尾行 |
| 无签名 exe 被企业策略阻止 | 中 | 无法运行 | 运行时使用官方 Node 签名二进制；提供企业部署说明 |
