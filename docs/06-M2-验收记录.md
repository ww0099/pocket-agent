## 3. 安全行为（已实现并测试）

| 机制 | 行为 |
|---|---|
| 危险命令硬拦截 | `format`、`diskpart`、`shutdown`、`bcdedit`、`reg delete HKLM`、`mkfs`、`dd if=`、`vssadmin delete`、`cipher /w` 等直接拒绝 |
| 破坏性命令标记 | `rm -rf`、`Remove-Item -Recurse`、`git reset --hard`、`git push --force` 等标记为破坏性，进入审批 |
| 路径边界 | 仅允许工作区与 `additionalDirectories` 内的路径；拒绝工作区外访问 |
| 敏感路径 | 拒绝 `.ssh`、`.aws`、`.gnupg`、`.kube`、`id_rsa`、`secrets.json` 等 |
| Agent 自身保护 | 拒绝对 `config/runtime/app/tools` 的写操作与磁盘根目录写入 |
| 读后写 | Write/Edit 已存在文件前必须先 Read；未读直接拒绝 |
| 冲突检测 | 文件在读取后被外部修改（SHA-256 不一致）时拒绝写入 |
| 权限模式 | `default`（只读放行、写/命令询问）、`acceptEdits`、`plan`、`bypass` |
| 无交互默认 | headless 下需要授权的操作默认拒绝；`--yes` 自动批准（硬拦截仍生效） |
| 密钥脱敏 | 日志、错误信息中的已加载密钥替换为 `***` |

## 4. 已知限制（诚实口径）

| 限制 | 影响 | 计划 |
|---|---|---|
| 无交互式审批 UI | headless 下写/Bash 需 `--yes` 或 allow 规则 | M3 TUI 提供审批弹窗 |
| 未内置 ripgrep | `Grep` 走 JS 回退，扫描上限 5000 文件 / 单文件 1MB | M6 随盘装配 `rg.exe` |
| 后台命令无完成跟踪 | `run_in_background` 只返回 PID 与日志，不通知完成 | M4/M5 |
| 无编辑 diff 预览 | Edit 返回替换处数与行号 | M3 |
| 无上下文压缩 | 长会话仍可能撑爆 | M4 |
| 会话索引在关闭时更新 | 强杀进程后 `index.json` 可能滞后；`--continue` 通过扫描文件兜底 | M4 优化 |
