# 02 · 架构设计

> 版本：0.1（2026-10-22）  
> 目标：在 Windows U 盘上运行、多 Provider、可扩展的本地 Agent 平台  
> 设计基准：Claude Code 2.1.x 的分层与执行模型（仅借鉴架构，独立实现）

---

## 1. 总体原则

1. **一个内核，多种形态**：交互式 TUI、headless、子 Agent 共用同一套 `agentLoop()`。
2. **UI 与内核解耦**：内核只产出事件流（`AsyncGenerator<AgentEvent>`），UI 只消费事件。
3. **权限是工具的一等属性**：每个工具自行声明只读/并发/破坏性/权限规则，调度器据此决策。
4. **Provider 是适配器**：内部消息模型与厂商协议解耦，新增厂商不改内核。
5. **状态全部落盘且可读**：会话 JSONL、记忆 Markdown、配置 JSON；不引入数据库。
6. **便携优先**：所有路径由 `AGENT_ROOT` 推导；不依赖用户目录、注册表、系统 Node。

## 2. 分层架构

```text
┌─────────────────────────────────────────────────────────────┐
│ L0 引导层                                                    │
│   agent.cmd → runtime\win-x64\node.exe → app\dist\cli.js    │
│   职责：设置 AGENT_ROOT / TEMP / 编码，转发参数与退出码        │
│   v2 预留：agent.sh → runtime\linux-x64\node                  │
├─────────────────────────────────────────────────────────────┤
│ L1 装配层（cli / bootstrap）                                 │
│   参数解析 → 定位项目根 → 加载配置 → 解析密钥 → 选择运行形态    │
│   → 注册 Provider / Tools / Skills / Agents / MCP / Commands │
├─────────────────────────────────────────────────────────────┤
│ L2 交互层（ui）                                              │
│   Ink REPL（交互）  |  Plain Printer（headless）             │
│   只消费事件流；不直接调用工具或 Provider                      │
├─────────────────────────────────────────────────────────────┤
│ L3 执行内核（core）                                          │
│   agentLoop()：组装上下文 → 流式调用 → 工具闭环 → 压缩检查     │
│   ContextManager：token 估算、压缩、附件复灌                  │
├─────────────────────────────────────────────────────────────┤
│ L4 能力层                                                    │
│   Tools（Read/Write/Edit/Glob/Grep/Bash/...）                │
│   Permissions（规则、模式、审批）                             │
│   Hooks（PreToolUse/PostToolUse/...）                        │
├─────────────────────────────────────────────────────────────┤
│ L5 模型层（providers）                                       │
│   统一接口 stream()；Anthropic 适配器 / OpenAI 兼容适配器      │
├─────────────────────────────────────────────────────────────┤
│ L6 状态层（session / memory / cost / log）                   │
│   JSONL 会话、MEMORY.md、用量统计、分级日志                   │
├─────────────────────────────────────────────────────────────┤
│ L7 扩展层（extensions）                                      │
│   MCP Client | Skills Loader | Agent Registry | Command Reg. │
└─────────────────────────────────────────────────────────────┘
```

依赖方向：**L2 → L3 → L4/L5/L6 → L7**。内核不 import UI；Provider 不 import 工具；工具不 import UI。

## 3. 运行形态

| 形态 | 入口 | 特征 |
|---|---|---|
| 交互式 REPL | `agent.cmd` | Ink TUI、流式输出、审批弹窗、斜杠命令 |
| Headless | `agent.cmd -p "..."` | 纯文本输出、自动权限策略、适合管道与 CI |
| 子 Agent | `Task` 工具内部 | 无 UI、独立消息历史、只回传最终结论 |
| 自检 | `agent.cmd doctor` | 检查运行时/配置/密钥/网络/工具链 |

四种形态共用 `runAgent()`，仅注入不同的 `UiAdapter` 与权限策略。

## 4. 一次请求的生命周期

  │      │
  │      ▼

  │      │
  │      ▼

         ▼

## 6. 核心数据模型

### 6.1 统一消息模型

内部不直接使用任何厂商格式，避免内核被单一协议污染。

```ts
// src/core/messages.ts
export type ContentBlock =
  | { type: 'text'; text: string }
  | { type: 'tool_use'; id: string; name: string; input: unknown }
  | { type: 'tool_result'; toolUseId: string; content: string; isError: boolean }
  | { type: 'image'; mediaType: string; data: string }; // base64，v1.5 启用

export interface Message {
  role: 'user' | 'assistant';
  content: ContentBlock[];
  meta?: {
    timestamp: number;
    model?: string;
    usage?: Usage;
  };
}
```

适配器负责双向映射：

| 内部模型 | Anthropic | OpenAI 兼容 |
|---|---|---|
| `tool_use` | `content[].type=tool_use` | `assistant.tool_calls[]` |
| `tool_result` | `user.content[].type=tool_result` | `role=tool` + `tool_call_id` |
| `usage` | `input_tokens/output_tokens/cache_*` | `prompt_tokens/completion_tokens` |
| 流式 | `content_block_delta` | `choices[].delta` |

### 6.2 Provider 接口

```ts
// src/providers/types.ts
export interface ProviderCapabilities {
  toolUse: boolean;
  parallelToolCalls: boolean;
  streaming: boolean;
  promptCaching: boolean;
  maxContextTokens: number;
  maxOutputTokens: number;
}

export interface StreamRequest {
  system: string;
  messages: Message[];
  tools: ToolSchema[];
  model: string;
  temperature?: number;
  maxTokens?: number;
  signal: AbortSignal;
}

export interface Provider {
  readonly id: string;
  readonly capabilities: ProviderCapabilities;
  stream(req: StreamRequest): AsyncGenerator<AgentEvent>;
}
```

### 6.3 归一化事件流

```ts
// src/core/events.ts
export type AgentEvent =
  | { type: 'text_delta'; text: string }
  | { type: 'thinking_delta'; text: string }        // 可选
  | { type: 'tool_call_start'; id: string; name: string }
  | { type: 'tool_call_delta'; id: string; argsText: string }
  | { type: 'tool_call_end'; id: string; input: unknown }
  | { type: 'usage'; usage: Usage }
  | { type: 'stop'; reason: StopReason }
  | { type: 'tool_result'; id: string; name: string; result: ToolResultView }
  | { type: 'notice'; level: 'info' | 'warn'; text: string }
  | { type: 'error'; message: string; retryable: boolean };
```

UI 只依赖这个联合类型；新增 Provider 不影响 UI。

## 7. 工具系统

### 7.1 Tool 接口

```ts
// src/tools/base.ts
export interface ToolContext {
  cwd: string;
  roots: string[];                 // 允许访问的根目录
  sessionId: string;
  signal: AbortSignal;
  permissions: PermissionGate;
  logger: Logger;
  ui: UiHooks;                     // 仅用于进度/审批，不直接渲染
}

export interface Tool<I = unknown> {
  name: string;
  description: string;
  inputSchema: z.ZodType<I>;

  isReadOnly(input: I): boolean;
  isConcurrencySafe(input: I): boolean;
  isDestructive(input: I): boolean;
  checkPermissions(input: I, ctx: ToolContext): PermissionDecision;

  call(
    input: I,
    ctx: ToolContext,
    onUpdate: (u: ToolProgress) => void,
  ): Promise<ToolResult>;          // 内部可流式上报进度
}

export interface ToolResult {
  output: string;                  // 进入上下文的（可能已截断）
  fullOutputPath?: string;         // 全文落盘路径
  isError: boolean;
  metadata?: Record<string, unknown>;
}
```

默认值遵循 **fail-closed**：未声明即"非只读、非并发安全、需权限"。

### 7.2 工具调度

```ts
// src/core/scheduler.ts（设计）
function partition(calls: ToolCall[], ctx: ToolContext): Batch[] {
  return calls.reduce<Batch[]>((batches, call) => {
    const tool = registry.get(call.name);
    const safe = tool?.isConcurrencySafe(call.input) ?? false;
    const last = batches.at(-1);
    if (safe && last?.safe) last.calls.push(call);
    else batches.push({ safe, calls: [call] });
    return batches;
  }, []);
}
```

规则：

- 只读且声明并发安全的工具（Read/Glob/Grep）成批并发；
- Write/Edit/Bash 永远串行，且按模型给出的顺序执行；
- 同一批次中任一失败不取消其他只读工具，但串行批次遇失败即停止后续写操作；
- 每个工具都有 AbortSignal，用户取消时立即终止。

### 7.3 工具结果治理

- 单次输出上限（默认 30KB / 2000 行）；超出时保留头 100 行 + 尾 100 行；
- 全文写入 `data\tool-outputs\<sessionId>\<toolUseId>.txt`；
- 截断提示明确告诉模型："已截断，全文位于 <绝对路径>，可用 Read 分段读取"；
- 二进制文件拒绝读入上下文，返回元信息。

## 8. 权限系统

### 8.1 决策模型

```ts
export type PermissionDecision =
  | { behavior: 'allow'; reason: string }
  | { behavior: 'deny'; reason: string }
  | { behavior: 'ask'; reason: string; rule?: string };
```

判定顺序（先命中先返回）：

1. 硬性黑名单（系统目录、密钥目录、危险命令）→ `deny`（不可被普通规则覆盖）；
2. `bypass` 模式 → `allow`（但仍记录审计日志）；
3. `plan` 模式 → 写操作一律 `deny`，只读放行；
4. 项目级 deny 规则 → `deny`；
5. 项目级 allow 规则 → `allow`；
6. 用户级 deny/allow 规则；
7. 工具默认策略（只读 → allow；写/网络 → ask；Bash → ask）；
8. `acceptEdits` 模式下 Edit/Write → allow。

### 8.2 规则 DSL

```jsonc
{
  "allow": [
    "Read",
    "Glob",
    "Grep",
    "Bash(git status:*)",
    "Bash(npm test:*)",
    "Bash(npm run *)",
    "WebFetch(domain:github.com)"
  ],
  "deny": [
    "Read(**/.env)",
    "Read(**/*.pem)",
    "Bash(rm -rf:*)",
    "Bash(format:*)",
    "Bash(shutdown:*)"
  ]
}
```

匹配语义：

- `Tool` — 该工具全部动作；
- `Tool(prefix:*)` — 参数以 `prefix` 开头的 Bash 命令；
- `Tool(glob)` — 文件类工具的路径 glob（区分大小写由文件系统决定）；
- `Tool(domain:host)` — 网络类工具的目标域名；
- 规则中的相对路径相对于**项目根**解析。

### 8.3 审批交互

```text
⚠ Bash 请求执行：
   npm run build

  [a] 允许本次   [A] 本项目始终允许   [d] 拒绝   [e] 编辑命令
```

选择"始终允许"时写入项目 `.agent\permissions.json`（不是 U 盘全局），避免把某个项目的信任扩散到所有项目。

## 9. 上下文管理

### 9.1 系统提示组成（按顺序）

1. 身份与行为准则（简洁、先读再改、最小改动、不臆测）；
2. 环境信息：OS、shell、cwd、项目根、日期、Git 状态摘要；
3. 工具使用准则（何时用 Grep 而非 Bash、编辑前必须 Read 等）；
4. 权限与安全边界说明；
5. 记忆：全局 `MEMORY.md` + 项目 `.agent\memory\MEMORY.md`（各限 200 行 / 25KB）；
6. 项目说明：`AGENTS.md` / `CLAUDE.md`（向上查找，取最近一处）；
7. 技能索引：`name — description`（仅元数据，正文按需加载）；
8. 子 Agent 索引：`name — description`；
9. 当前任务状态：Todo 清单、最近修改文件。

### 9.2 Token 估算

```ts
// 混合文本的保守估算：CJK 按 1 token/字，其余按 4 字符/token
export function estimateTokens(text: string): number {
  const cjk = (text.match(/[\u3000-\u9fff\uff00-\uffef]/g) ?? []).length;
  const rest = text.length - cjk;
  return Math.ceil(cjk + rest / 3.5);
}
```

每次 API 返回的 `usage.input_tokens` 用于校准估算系数（滑动平均）。估算只用于触发压缩，不用于计费展示（计费以 Provider 返回为准）。

### 9.3 压缩策略

| 策略 | 触发 | 行为 |
|---|---|---|
| 自动压缩 | 估算 ≥ 窗口 × 0.75 | 摘要早期历史，保留最近 6~10 轮 + 所有未完成待办 |
| 手动 `/compact [指令]` | 用户 | 同上，可附加"重点保留 X" |
| 工具输出截断 | 单次结果超限 | 头尾保留 + 全文落盘 |
| 大文件保护 | Read 超 2000 行 | 强制分段，提示剩余行数 |

压缩后**复灌**（关键，避免"失忆"）：

- 当前 cwd、项目根、Git 分支；
- 最近修改过的文件列表（路径 + 一句话说明）；
- 未完成的 Todo；
- 已加载的技能 / 子 Agent；
- 当前权限模式与关键规则；
- 上一次压缩的摘要（链式摘要）。

### 9.4 长会话的稳定性

- 每轮结束检查一次压缩，不在流式过程中压缩；
- 压缩失败（如摘要请求超长）时降级为"硬截断 + 保留关键附件"；
- 压缩结果作为一条 `compaction` 记录写入会话，可回放。

## 10. 会话与记忆

### 10.1 会话存储

```text
data\sessions\<projectKey>\<sessionId>.jsonl
data\sessions\index.json
```

`projectKey = <basename>-<sha256(realpath(cwd))[:12]>`，避免不同项目同名冲突；同时保留可读性。

JSONL 记录类型：

```jsonc
{"type":"session_start","id":"...","cwd":"...","model":"...","ts":...}
{"type":"user","content":[{"type":"text","text":"..."}],"ts":...}
{"type":"assistant","content":[...],"usage":{...},"ts":...}
{"type":"tool_result","toolUseId":"...","content":"...","isError":false,"ts":...}
{"type":"compaction","summary":"...","upToMessageId":"...","ts":...}
{"type":"session_end","reason":"exit","ts":...}
```

写入策略：**追加写 + 每条消息 flush**。崩溃时最多丢失半行，启动时丢弃无法解析的尾行。

### 10.2 恢复会话

`--continue`：取当前项目最近一个会话；`--resume <id>`：按 ID 恢复。
恢复流程：读 JSONL → 重建消息 → 找到最后一次 compaction → 只加载其后消息 + 摘要 → 校验文件状态（最近修改文件是否被外部改动）。

### 10.3 记忆

| 层级 | 位置 | 生命周期 |
|---|---|---|
| 全局记忆 | `<root>\memory\MEMORY.md` + 条目文件 | 随 U 盘 |
| 项目记忆 | `<project>\.agent\memory\MEMORY.md` | 随项目 |
| 会话记忆 | 会话 JSONL 的压缩摘要 | 随会话 |

记忆格式：`MEMORY.md` 是索引，每条一行链接；条目文件为 Markdown，含 frontmatter（`name/description/type`）。注入时只读索引并硬截断，避免 prompt 膨胀。

## 11. 扩展机制

### 11.1 MCP

```jsonc
// config\mcp.json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "D:\\work"],
      "env": {}
    },
    "remote-tools": {
      "url": "https://example.com/mcp",
      "headers": { "Authorization": "Bearer ${MCP_TOKEN}" }
    }
  }
}
```

- 启动时并发连接，单个超时 5s，失败仅告警；
- 工具名统一为 `mcp__<server>__<tool>`；
- MCP 工具的权限规则与内建工具一致；
- 只读注解（`readOnlyHint`）可使其参与并发调度；
- v1 只支持 tools；resources / prompts 放 v1.5。

### 11.2 Skills（渐进披露）

```text
skills\code-review\
├── SKILL.md
└── references\checklist.md
```

```markdown
---
name: code-review
description: 按团队规范审查代码变更
when_to_use: 用户要求 review / 审查 PR / 检查改动时
---

# Code Review
（正文：步骤、检查项、输出格式）
```

- 启动时只扫描 frontmatter，把 `name + description` 注入系统提示（每条 ≤ 1 行）；
- 模型调用 `Skill(name)` 时才读取正文；
- 正文中的相对路径以技能目录为基准解析；
- 项目级技能覆盖同名全局技能。

### 11.3 Subagents

```markdown
---
name: explore
description: 只读探索代码库，返回结构结论
tools: [Read, Glob, Grep]
model: inherit
maxTurns: 12
---

你是代码探索专家。只读，不修改文件。返回：入口、模块、关键文件、风险点。
```

- 子 Agent 拥有独立消息历史，不继承父上下文（只接收任务描述）；
- 工具白名单在运行前强制过滤；
- 只把最终结论回传父 Agent，避免上下文污染；
- v1 限制递归深度为 1，防止失控。

### 11.4 自定义命令

```markdown
<!-- commands\review.md -->
---
description: 审查当前分支的改动
argument-hint: [base-branch]
---
审查 ${1:-main} 到 HEAD 的改动，按项目 AGENTS.md 的规范输出问题清单。
```

支持 `${1}` 位置参数与 `${@}` 全量参数。

### 11.5 Hooks（v1.1）

```jsonc
// config\hooks.json
{
  "PreToolUse": [
    { "matcher": "Bash", "command": "node hooks\\check-command.js", "timeout": 5000 }
  ]
}
```

Hook 从 stdin 读取 JSON（工具名、输入、cwd），退出码 `2` 表示阻止执行，stdout 可作为拒绝原因。Hook 本身不获得 API Key。

## 12. 便携化设计

### 12.1 根目录推导

```ts
// src/bootstrap/root.ts
export function resolveAgentRoot(): string {
  if (process.env.AGENT_ROOT) return path.resolve(process.env.AGENT_ROOT);
  // cli.js 位于 <root>\app\dist\cli.js
  return path.resolve(__dirname, '..', '..');
}
```

所有路径统一从这里派生，**禁止**使用 `os.homedir()`、`%APPDATA%`、`%TEMP%` 保存状态。

### 12.2 启动器

```bat
@echo off
setlocal
set "AGENT_ROOT=%~dp0"
set "TEMP=%AGENT_ROOT%data\tmp"
set "TMP=%AGENT_ROOT%data\tmp"
set "NODE_NO_WARNINGS=1"
if not exist "%AGENT_ROOT%data\tmp" mkdir "%AGENT_ROOT%data\tmp"
"%AGENT_ROOT%runtime\win-x64\node.exe" "%AGENT_ROOT%app\dist\cli.js" %*
exit /b %ERRORLEVEL%
```

要点：

- `%~dp0` 自带尾部反斜杠，且能正确处理空格与中文路径；
- `.cmd` 必须 **CRLF** 换行；
- 不修改系统环境变量，`setlocal` 保证退出即还原；
- 退出码透传，便于脚本调用。

### 12.3 exFAT 适配

- 不使用符号链接、硬链接、junction；
- 避免大小写仅不同的文件名；
- 原子写：同目录写 `.tmp` → `fs.renameSync`；
- 日志按大小滚动（默认 5MB × 3），避免磨损；
- 会话 JSONL 追加写，不做全文重写；
- 目录层级保持浅（≤ 4 层），控制长路径风险；
- 构建产物打包为少量大文件，避免数千个小文件拖慢 U 盘。

### 12.4 不写 C 盘

- 启动器重定向 `TEMP/TMP`；
- 运行时不调用 npm / npx 安装（MCP Server 若需 npx 会写缓存，需显式告警并提供"随盘 node_modules"方案）；
- 日志、会话、缓存全部在 `AGENT_ROOT\data`；
- 子进程继承重定向后的环境变量；
- 提供 `/doctor` 检查项：列出所有被写入的根路径。

### 12.5 平台抽象层（跨平台预留）

v1 只交付 Windows，但**不允许**把 Windows 假设散落到业务代码里。所有平台差异集中在 `util\platform.ts`：

```ts
export interface PlatformAdapter {
  readonly id: 'win32' | 'darwin' | 'linux';
  readonly arch: 'x64' | 'arm64';

  /** 运行时目录名，如 win-x64 / darwin-arm64 */
  runtimeDirName(): string;
  /** 可执行文件后缀，如 .exe / '' */
  exeSuffix(): string;
  /** 启动器文件名，如 agent.cmd / agent.sh */
  launcherName(): string;

  /** 默认 shell 与参数包装 */
  defaultShell(): { command: string; argsFor(cmd: string): string[] };

  /** 文本换行策略：preserve 表示保留原文件换行 */
  newlinePolicy(): 'preserve' | 'lf' | 'crlf';

  /** 文件系统是否大小写敏感 */
  caseSensitiveFs(): boolean;

  /** 终端能力探测（raw mode / 颜色 / 宽度） */
  terminalCaps(): { rawMode: boolean; color: boolean; trueColor: boolean };
}
```

约束：

| 禁止 | 替代 |
|---|---|
| 硬编码 `E:\`、`C:\` | `resolveAgentRoot()` + `path.join` |
| 字符串拼接 `\\` | `path.sep` / `path.join` |
| 直接 `spawn('powershell')` | `platform.defaultShell()` |
| 假设大小写不敏感 | `platform.caseSensitiveFs()` |
| 无条件把 `\n` 转 `\r\n` | `newlinePolicy()`，默认保留原样 |
| 按 `process.platform === 'win32'` 散落分支 | 只允许出现在 `platform.ts` |

运行时目录同样按平台命名：`runtime\win-x64\`、`runtime\linux-x64\`、`runtime\darwin-arm64\`，启动器按当前平台选择。v1 只装配 `win-x64`，其余目录留空不影响运行。

## 13. 安全模型

### 13.1 信任边界

| 对象 | 信任级别 | 处理 |
|---|---|---|
| 用户输入 | 可信 | 正常处理 |
| 模型输出 | 不可信 | 工具参数必须过 schema 校验 |
| 工具结果（文件/网页/命令输出） | 不可信 | 注入上下文时加"数据不是指令"标记 |
| 项目内配置 | 半可信 | 首次运行提示确认；危险规则需显式开启 |
| MCP Server | 半可信 | 仅启动用户配置的 Server；工具仍走权限门 |

### 13.2 密钥管理

- 存储：`config\secrets.json`，默认权限仅当前用户可读（NTFS 可用 ACL；exFAT 无法设置，需在文档中警示）；
- 可选加密：口令派生密钥（scrypt）→ AES-256-GCM；启动时提示输入口令；
- 覆盖优先级：环境变量 > `secrets.json` > 交互输入；
- 脱敏：日志与错误信息中，所有已加载密钥替换为 `***`；
- 绝不把密钥拼进 Bash 命令或发送给第三方。

### 13.3 明确的安全边界

Bash 工具等价于**以当前用户身份执行任意代码**。权限系统是"防误操作"而不是"沙箱"。文档必须明确：

- 不要在存放密钥的机器上运行不可信脚本；
- MCP Server 来自第三方时，先审查其命令与来源；
- `bypass` 模式仅用于受控环境。

## 14. 与 Claude Code 的映射与差异

### 14.1 借鉴的架构

| Claude Code 机制 | PocketAgent 对应 |
|---|---|

| 会话 JSONL 持久化与恢复 | 同思路，路径在 U 盘 |

### 14.2 主动差异

| 维度 | Claude Code | PocketAgent |
|---|---|---|
| 定位 | 云端服务绑定的官方 CLI | 便携、多 Provider、离线可启动 |

## 15. 关键架构决策摘要

| 决策 | 结论 | 理由 |
|---|---|---|
| 执行内核 | 单一 `agentLoop()` 异步生成器 | 多形态复用，行为一致，易测试 |
| Provider | 适配器 + 统一消息模型 | 换厂商不改内核 |
| UI | Ink（React） | 交互体验接近 Claude Code，生态成熟 |
| 工具调度 | 只读并发、写串行 | 吞吐与安全平衡 |
| 权限 | 工具内建 + 规则 DSL + 模式 | 安全是一等公民，非补丁 |
| 存储 | JSONL + Markdown + JSON | 可读、可审计、无数据库依赖 |
| 构建 | esbuild 单文件 bundle | U 盘小文件性能差，减少文件数 |
| 运行时 | 官方 Node 便携版 | 零安装、可信签名、兼容性好 |
